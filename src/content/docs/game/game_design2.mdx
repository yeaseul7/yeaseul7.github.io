# Supercell: 좋은 게임을 만드는 개발 방식

게임 기획만큼 중요한게 아이디어 검증일 것 같다.

Supercell의 CEO Ilkka Paananen이 작성한 *Comfortable Feeling Uncomfortable*에서는 기존의 개발 방식을 바꾸게 된 이유와 새로운 개발 방향을 소개한다.

## 1. Supercell은 왜 개발 방식을 바꿨을까?

Supercell은 클래시 오브 클랜, 클래시 로얄, 브롤스타즈 등 여러 인기 게임을 개발했다.

하지만 2023년 당시에는 기존 게임의 성장세가 둔화되었고, 2018년 브롤스타즈 이후 신작을 출시하지 못한 상황이었다.

이를 해결하기 위해 Supercell은 **신작 개발과 기존 게임 운영을 서로 다른 방식으로 접근**하기로 했다.

| 구분                   | 개발 방향                                    |
| ---------------------- | -------------------------------------------- |
| New Games as Startups  | 신작 개발팀을 독립적인 스타트업처럼 운영     |
| Live Games as Scaleups | 성공한 게임은 조직과 운영 규모를 확대해 성장 |

## 2. New Games as Startups: 스타트업처럼 개발하기

Supercell은 신작 개발팀이 빠르게 실험하고 스스로 의사결정을 내릴 수 있는 환경을 중요하게 생각한다.

### ① 아이디어보다 팀을 중요하게 생각한다

구현할 역량을 가진 팀이 없다면 성공하기 어렵다.

그래서 팀원의 역량, 실행력, 협업 능력을 중요하게 평가한다.

### ② 자율성을 보장하되 책임을 요구한다

개발팀이 스스로 방향을 결정할 수 있도록 자율성을 보장한다.

대신 주요 일정, 개발 목표, 필요한 자원을 정하고 이를 회사에 투명하게 공유하도록 한다.

### ③ 실제 플레이어에게 빠르게 검증한다

Supercell은 게임을 가능한 한 빨리 플레이어에게 보여주고 반응을 확인하는 것을 강조한다.

- 반응이 좋다면 개발에 더 투자한다.
- 반응이 좋지 않다면 방향을 수정한다.

오랫동안 개발한 뒤에야 재미가 없다는 사실을 알게 되면 수정하기 어려워지기 때문이다.

이 과정은 **Product-Market Fit(PMF)**, 즉 게임이 실제 플레이어의 수요에 맞는지 확인하는 과정과 연결된다.

### ④ 개발에만 집중할 수 있는 환경을 만든다

초기 개발팀은 불필요한 업무와 절차를 줄이고 게임 제작에 집중할 수 있도록 지원받는다.

프로토타입 제작에서도 사내 엔진만 고집하지 않고 Unity, Unreal 등 필요한 도구를 자유롭게 선택할 수 있다.

어떤 기술을 사용했는지보다 빠르게 게임의 가능성을 검증하는 것이 중요하다는 것이다.

## 3. Live Games as Scaleups: 성공한 게임은 다르게 운영한다

신작 개발의 목표가 재미있는 게임을 발견하는 것이라면, 라이브 게임은 이미 검증된 재미를 발전시키는 데 집중한다.

Supercell은 이를 위해 기존의 작은 팀 구조를 고집하지 않고, 필요에 따라 조직을 확대하는 방식을 선택했다.

- 새로운 콘텐츠와 기능 추가
- 기존 플레이 경험 개선
- 플레이어 규모 확대
- 장기적인 서비스 운영

팀을 작게 유지하는 것 자체보다 **플레이어에게 더 좋은 게임을 제공하는 것**이 중요하다고 판단한 것이다.

## 4. 1인 인디게임 개발에 적용한다면?

혼자 게임을 개발할 때도 Supercell의 방식에서 참고할 부분이 있다.

### ① 처음부터 완성하려고 하지 않기

게임의 모든 기능을 구현하기 전에 핵심 재미를 확인할 수 있는 프로토타입부터 만든다.

예를 들어 경매 게임이라면 화려한 연출이나 다양한 아이템보다 입찰과 낙찰 과정이 재미있는지 먼저 확인하는 것이다.

### ② 개발 중간에 플레이테스트하기

개발자가 재미있다고 생각하는 것과 실제 플레이어가 재미있어하는 것은 다를 수 있다.

따라서 어느 정도 플레이가 가능해지면 다른 사람에게 테스트를 부탁하고 다음 사항을 확인한다.

- 규칙을 쉽게 이해하는가?
- 어떤 순간에 재미를 느끼는가?
- 다시 플레이하고 싶어 하는가?

### ③ 필요하다면 과감하게 수정하기

이미 시간을 투자한 기능이더라도 게임의 재미에 도움이 되지 않는다면 수정하거나 제거할 수 있어야 한다.

기능을 많이 만드는 것보다 재미있는 게임을 완성하는 것이 중요하기 때문이다.

## 5. 정리

Supercell의 개발 방식에서 가장 인상적이었던 점은 신작과 기존 게임을 구분하고, 실제 플레이어의 반응을 중요하게 생각한다는 것이었다.

혼자 개발할 때는 기획부터 디자인, 개발까지 모두 직접 해야 하다 보니 하나의 기능에 많은 시간을 사용하기 쉽다.

앞으로는 처음부터 모든 것을 완성하기보다 **핵심 재미를 먼저 구현하고, 빠르게 테스트하면서 개선하는 방식**으로 개발해 보려고 한다.
