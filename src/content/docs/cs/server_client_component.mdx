### React의 컴포넌트

react의 컴포넌트는
브라우저에서 js 파일을 이용해서 컴포넌트를 실행합니다.

```
JavaScript 번들 다운로드
        ↓
JavaScript 실행
        ↓
React 컴포넌트 실행
        ↓
React Element Tree 생성
        ↓
실제 DOM에 반영
        ↓
브라우저 화면 렌더링
        ↓
사용자 이벤트 처리
```

### 서버 컴포넌트(Server Component)

서버 컴포넌트란 **서버 환경에서 실행되는 컴포넌트**입니다.

기존의 클라이언트 컴포넌트는 JavaScript를 브라우저로 전달하고 UI를 구성합니다.<br/>
하지만 컴포넌트가 브라우저에서 실행될 필요는 없습니다.

예를 들어서 서버에서 받아온 상품 목록을 단순히 보여주는 컴포넌트를 생각해보면

```tsx
function ProductList({ products }) {
  return (
    <ul>
      {products.map((product) => (
        <li key={product.id}>{product.name}</li>
      ))}
    </ul>
  );
}
```

이 컴포넌트는 사용자 이벤트 없이 데이터만 보여줍니다.

브라우저에서 실행한다면 해당 컴포넌트를 실행하기 위한 JavaScript를 다운로드하고 파싱하고 실행해야 합니다.

Server Component는 이것을 **서버에서 먼저 수행**합니다.

```text
서버
  ↓
데이터 조회
  ↓
Server Component 실행
  ↓
UI에 필요한 결과 생성
  ↓
브라우저로 전달
```

데이터베이스나 API에서 데이터를 조회한 뒤 바로 UI를 구성합니다.<br/>
그리고 해당 코드는 클라이언트 번들에 포함되지 않습니다.

그러면 브라우저가 다운로드하고 실행해야 하는 JavaScript의 양을 줄일 수 있습니다.

본질은 다음과 같습니다.

> **컴포넌트 실행 위치를 서버로 옮긴 것.**

주의할 것은 모든 컴포넌트를 Server Component로 만들 수 있는 것은 아닙니다. <br/>
`useState`, `onClick`같은 상호작용해야 하는 부분은 Client Component가 담당해야 합니다.
사용자가 직접 상호작용하는 부분은 서버에서 처리할 수 없기 때문입니다.

ProductList 같은 컴포넌트는 서버에서 바로 데이터를 받는게 더 빠르게 구성할 수 있습니다.<br/>
따라서 이런경우 서버 컴포넌트를 사용합니다.<br/>
Server Component를 이런식으로 사용하면 브라우저 입장에서 처리해야되는 js양이 줄어듭니다.

### 클라이언트 컴포넌트(Client Component)

클라이언트 컴포넌트란 **브라우저 환경에서 실행되는 컴포넌트**입니다.

`onClick`과 같은 사용자 이벤트가 발생하면 브라우저에서 이벤트를 처리하고 상태를 변경합니다.

`useState`와 같은 상태는 브라우저 메모리에 저장됩니다.<br/>
상태가 변경되면 해당 상태를 사용하는 컴포넌트가 다시 렌더링되어 화면이 갱신됩니다.

`"use client"`는 Next.js에서 클라이언트 컴포넌트를 정의하는 방법입니다. <br/>
Next.js는 기본적으로 서버 컴포넌트로 동작합니다.

## AI 질문

### Server Component는 왜 클라이언트 번들 크기를 줄일 수 있나요?

서버에게 통신을 받아서 데이터를 받아오고 이후에 구성되는 컴포넌트를 구성하는것이기 때문에
브라우저에서 초기에 구성하는 번들에 포함될 필요가 없기 때문입니다.

#### 7/10

좋은 점은 “브라우저 초기 번들에 포함될 필요가 없다”는 핵심을 잡았다는 거야. 다만 서버에서 데이터를 받아오기 때문이 본질은 아니야. 데이터 조회가 없어도 Server Component일 수 있어.

-> Server Component의 실행 코드가 브라우저용 JavaScript 번들에 포함되지 않기 때문에 클라이언트가 다운로드하고 실행할 JavaScript 양이 줄어든다.

### "use client"를 상위 컴포넌트에 붙이면 어떤 영향이 생기나요?

기본적으로 서버 컴포넌트로 동작해서 번들링 크기를 줄이는 효과를 죽일 수 있습니다. <br/>
번들링 크기를 크게 만들고 초기 렌더링이 느려지는 효과가 생깁니다. <br/>

#### 8/10

방향은 좋았어. 특히 번들 크기가 커질 수 있다는 점을 잘 짚었어.<br/>
초기 렌더링이 느려진다

는 너무 단정적이야. 항상 느려지는 건 아니니까,<br/>
불필요한 JavaScript가 클라이언트 번들에 포함되어 다운로드·파싱·실행 비용이 증가할 수 있다.

정도로 이해하면 더 정확해.

### Server Component에서 가져온 데이터를 Client Component에 전달할 수 있나요? 가능하다면 어떤 방식으로 전달되나요?

전달할 수 있습니다 서버 컴포넌트에서 받아서 구성된 컴포넌트를 props로 클라이언트 컴포넌트에게 전달하고 이를 state로 관리할 수 있습니다.

#### 7/10

props로 전달한다는 핵심은 정확해.<br/>
이를 state로 관리할 수 있습니다.

여기야. state로 바꿀 필요는 없어. 단순 출력이라면 props 그대로 쓰면 돼.
`<ClientComponent products={products} />`

그리고 심층 질문답게 답하려면 하나 더 붙여야 해.<br/>
Server Component에서 Client Component로 전달하는 props는 직렬화 가능한 값이어야 한다.
