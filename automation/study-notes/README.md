# ChatGPT 학습 기록 플러그인

커스텀 GPT나 별도 MCP 서버 대신 `학습 기록` 스킬과 기존 GitHub 연결을 사용한다. 브라우저 ChatGPT에서 이 플러그인을 선택해 공부한다.

## 연결

1. 이 저장소의 게시 workflow, scripts, `.study-inbox/.gitkeep`을 main에 반영한다.
2. `plugins/study-notes` 폴더를 Plugin Creator로 비공개 플러그인으로 생성한다. 로컬 파일만 만들어서는 브라우저에 설치되지 않는다.
3. 생성된 플러그인 링크에서 설치하고 GitHub 연결을 확인한다. 저장소 접근과 쓰기는 기존 GitHub 권한을 따른다. 새 토큰이나 API 키를 채팅에 입력하지 않는다.
4. 브라우저 ChatGPT에서 `@학습 기록`을 선택한다. 플러그인 사용·설치 제공 여부는 계정과 작업 공간에 따라 다르다.

## 사용

평소처럼 질문하며 공부한 뒤 `오늘 공부한 내용을 검토해서 블로그에 올려 줘`라고 요청한다. 단순히 `정리해 줘`라고 하면 초안까지만 만든다. 일반 채팅의 모든 대화를 자동 수집하지 않으며 현재 대화에서 접근 가능한 내용만 정리한다.

글은 대화 요약을 넘어 기술의 배경·내부 원리·한계와 선택 기준을 설명하는 개인 맞춤형 심층 아티클을 목표로 한다. 처음에는 짧은 핵심 요약을 두고, 주제에 맞는 목차와 하나의 발전하는 사례로 원인과 동작을 연결한다. 실제 질문과 오해 수정, 중간 이해도 확인, 최종 복습 문제와 해설을 필요한 위치에 배치한다. 고정된 제목이나 문제 수는 강제하지 않는다.

공식 자료에서 확인한 사실, 직접 실행한 결과, 개인적인 추론을 구분한다. 직접 하지 않은 실험이나 개발 경험은 쓰지 않는다. 자료를 확인하지 못하거나 핵심 오류가 해결되지 않으면 게시를 중지한다. 실행하지 않은 코드는 미실행 예제로 구분한다.

## 게시 처리

GitHub 플러그인은 최종 공개 글의 category·slug·title·description·body를 `.study-inbox/{slug}.json`에 생성한다. 이 push가 `Publish study note`를 실행한다. Actions는 미처리 요청을 읽어 허용된 카테고리에 `.md`를 생성하고, 테스트·타입 검사·빌드를 통과하면 Markdown 추가와 요청 JSON 제거를 한 커밋으로 저장한다. 이후 기존 배포 workflow를 명시적으로 실행한다.

GitHub Pages는 정적 호스팅이므로 게시 API 서버로 사용하지 않는다. 실제 내용 대조와 글의 깊이 검토는 ChatGPT가 수행한다. Actions는 제목을 강제하지 않고 본문에서 실제 참조한 출처 링크, 안전한 경로·Markdown·빌드를 검사한다. 코드 블록 속 링크나 사용하지 않는 참조 정의는 출처로 인정하지 않는다. 이 검사는 기술적 정확성과 글의 깊이를 보장하지 않는다.

## 실패와 재시도

- 검사가 실패하면 해당 Markdown은 원격에 커밋되지 않는다. 요청 JSON은 남으므로 실행 로그를 확인하고 수정해야 한다. 요청 파일도 공개 저장소 기록이므로 검토한 공개 글만 제출한다.
- 잘못된 요청은 보존하고 나머지 정상 요청을 처리한다. workflow 성공 여부만 보지 말고 해당 Markdown의 생성과 요청 제거를 확인한다.
- 기존 MD/MDX 글을 덮어쓰지 않는다. 기존 글 삭제는 아래 별도 요청으로 처리한다.
- 동시에 다른 main 변경이 발생하면 push가 거절될 수 있다. 최신 main 기준으로 workflow를 다시 실행한다. 강제 push하지 않는다.
- main 보호 규칙이 직접 push를 금지하면 PR 방식으로 변경해야 한다. 규칙을 임의로 해제하지 않는다.
- 커밋은 성공하고 배포 요청만 실패하면 `Deploy to GitHub Pages`를 main 기준으로 수동 실행한다.

## 글 삭제

`이벤트 루프 글 삭제해 줘`처럼 요청한다. 제목이 모호하면 후보 중 대상을 선택한다. 플러그인은 대상 파일을 읽어 정확한 경로와 현재 blob SHA를 확인하고 `.study-inbox/delete-{새 요청 ID}.json`을 생성한다.

```json
{
  "action": "delete",
  "category": "js",
  "slug": "event_loop",
  "extension": "mdx",
  "sha": "대상 파일의 실제 40자리 blob SHA"
}
```

Actions는 확인된 버전과 같은 단일 파일만 삭제하고, 타입 검사·빌드를 통과하면 삭제를 커밋하고 배포를 요청한다. 대상이 변경되거나 이미 없으면 중지한다. 실패한 요청은 검토를 위해 남는다. `action`이 없는 기존 요청은 계속 새 글 게시로 처리하며, `create`와 `delete` 이외의 작업은 거절한다.

글의 이미지·첨부파일·댓글은 자동으로 지우지 않는다. Git 이력은 남으므로 이전 커밋에서 복구할 수 있다. 과거 기록과 외부 사본을 영구 삭제하는 기능은 아니다.

## 글을 붙여 넣어 시험지 만들기

브라우저 ChatGPT에서 `@학습 기록`을 선택하고 학습 글과 함께 아래처럼 요청한다.

```text
아래 글로 이해도 점검 시험지를 만들어 줘.
4지선다 10문항으로, 상황 판단과 동작 원리를 중심으로 출제해 줘.
문제지 PDF와 정답·오답 해설 PDF를 따로 만들어 줘.

[학습 글 붙여 넣기]
```

기본은 A4 2단·4지선다 10문항이다. 질문·보기·이름 칸·메모 공간이 있는 문제지와, 정답 이유·보기별 오답 이유·원문 근거·복습 주제가 있는 답지를 분리한다. 원문이 짧으면 중복 문제로 수를 채우지 않는다. 출제 범위 밖의 지식이 필요하거나 정답이 모호한 문제는 수정·제외한다. 시험 제작만 요청하면 블로그에 게시하지 않는다.

PDF 생성에는 해당 ChatGPT 대화의 파일·코드 실행 기능, `reportlab`, 한글 TrueType 폰트가 필요하다. 사용할 수 없는 경우 문제지와 답지를 텍스트로 제공하고 PDF 생성 제한을 알린다. 스크립트는 로컬 경로를 고정하지 않고 설치된 스킬 파일에서 사용한다. 생성된 PDF는 이미지로 렌더링해 글자·배치·누락을 확인한다.

## 로컬 검증

```sh
node --test scripts/publish-study-note.test.mjs
npm run lint
npm run build
```

시험지 렌더러 검증은 `reportlab`과 `pypdf`가 있는 Python에서 실행한다.

```sh
python scripts/test-exam-pdf.py
```
